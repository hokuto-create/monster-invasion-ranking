# クラン幹部名簿 — 使い方メモ

魔物襲来ランキングのクラン合併を追跡するため、各クランのリーダー・副リーダー・長老の
名簿を時系列スナップショットとして `clans.json` に記録する。
同じプレイヤーが別クランの幹部として現れたら合併・移籍の手がかりになる。

## データ構造 (`clans.json`)

トップレベルは配列。1レコードが「あるクランのある時点のスナップショット」。

```json
{
  "recorded_at": "YYYY-MM-DD",
  "clan": { "name": "", "clan_id": 0, "level": 0, "members": "", "total_power": "" },
  "officers": [
    { "role": "", "name": "", "player_id": null, "power": "" }
  ]
}
```

- `player_id` は数値または `null`。スクショから取れないため後から手動で判明することがある
- `role` は「リーダー」「副リーダー」「長老」など

## 運用ルール

1. 別セッションでスクショから抽出した上記形式の JSON をチャットに貼る → `clans.json` に追記
2. 同じ `clan_id` の既存レコードがあっても**上書きせず**新スナップショットとして追加(履歴を残す)
3. 追記時に自動で「合併検知チェック」を実行。新レコードの幹部が過去の別 `clan_id` の
   レコードに幹部として存在していたら警告として報告
4. クラン名・プレイヤー名の特殊 Unicode 文字(結合文字、ﷻ 等)は**一切正規化・変換せず
   そのまま保存**。名前比較の際のみ `.normalize('NFC')` して照合する
5. 「player_id 更新」として `{"player_id": 123456, "name": "ゆえち"}` のような指定を貼ったら、
   全レコード中の同名(NFC 照合)の幹部に `player_id` を一括で埋める
6. 合併検知は `player_id` があれば ID 優先で照合、なければ名前照合にフォールバック
   (改名対策として ID の方が信頼できる)

## 検索スクリプト (`search.mjs`)

Node.js 単体で動く(依存なし)。このディレクトリで実行:

```bash
# プレイヤー名または player_id で全レコードを横断検索
node search.mjs player ゆえち
node search.mjs player 123456

# クランIDでスナップショット履歴を表示
node search.mjs clan 78910

# 全レコードを対象に合併検知チェック
node search.mjs check
```
